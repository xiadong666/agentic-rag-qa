# RAG 系统设计要点（示例知识库）

RAG（Retrieval-Augmented Generation，检索增强生成）是当前落地最多的 LLM 应用范式：先检索相关资料，再让模型基于资料生成答案，从而缓解幻觉并支持私有知识。

## 处理管线

典型管线：文档上传 → 解析（PDF/Word/Markdown）→ 文本分块 → 向量化 → 存入向量库 → 用户提问时检索 → 拼上下文 → 生成回答。

## 为什么需要混合检索

稠密向量擅长语义相似但会漏掉精确词（型号、人名、报错原文）；BM25 关键词检索对字面命中可靠但不懂同义改写。把两路结果用 RRF（Reciprocal Rank Fusion）融合：每个检索器按名次给分 1/(k+rank)，合并排序，简单且对分数尺度不敏感。

## 为什么要重排

混合检索的候选是粗粒度排序，噪声较多。精排用 cross-encoder：把（问题, 文档）拼起来过模型，让两边 token 互相看到对方，比 bi-encoder 各自编码再算相似度精细得多。代价是慢，所以只对少量候选精排。

## 引用来源的价值

每个分块都记录文档名与页码；生成时给资料编号并要求模型按 [n] 标注引用。这样回答可溯源、可验证、可审计，是 RAG 系统可信度的关键，也是演示与面试的亮点。

## 评估

RAG 效果要拆开评估：检索质量看召回率/命中率，生成质量看忠实度（是否忠于资料）与回答有用性，可用 RAGAS 等框架自动化打分。
