困难语料使用说明（sample_docs/hard）
================================================

这批文档是为了**测出系统的短板**而写的，不是"再来三篇速查"。
原来 sample_docs 里那 3 篇每篇只有 2 个分块、一篇一个主题，检索几乎不会错；
换成下面这 7 篇之后，才可能看出"检索准不准、回答相不相关"。

一、这批语料难在哪（七类模式，每篇主打一类）
------------------------------------------------
| 文件 | 类型 | 难在哪 |
| 01_网关与鉴权接入说明.md | 技术手册 | 同一参数出现 5000 / 3000 / 800 三个数字，只有 800 是默认值；术语有历史改名（Service Ticket → AGT） |
| 02_API变更记录.md | 版本日志 | 同一接口跨 7 个版本，分页参数改名 3 次（page→offset→cursor），必须"以最新版本为准"；末尾还埋了一条已知问题 |
| 03_数据平台运维手册.md | 长文档 | 关键阈值埋在第 6 节中部，前面 5 节都是铺垫；三条告警的处置动作很容易互相混淆 |
| 04_支付服务接口规范.md | 接口契约 | 金额单位是"分"不是"元"；状态机 7 个状态；签名 4 步里列了 3 个常见错误 |
| 05_部署与发布SOP.md | 流程规范 | 与 01/06 都在讲"上线"，但只有本文写了回滚判据 → 考语义干扰下的精确路由 |
| 06_Nexus_Gateway_Integration_Guide_EN.md | 英文文档 | 与 01 是同一主题的中英文两份，配额/有效期表述有差异 → 考跨语言与版本优先级 |
| 07_线上问题登记表.csv | 结构化数据 | 答案要按"服务名 + 是否可重试 + 时间最新"三个条件筛出来，不是语义匹配能解决的 |

二、配套文件
------------------------------------------------
test_cases.json   14 道题，每题带：期望命中的文档、回答必须覆盖的要点、这道题在考什么
                  其中 E12/E13/E14 是"库里确实没有答案"的幻觉探针

三、怎么用（两步）
------------------------------------------------
1) 灌库 + 检索验收（推荐先起服务，走真实 HTTP 链路）
     .venv-rag\Scripts\python -m uvicorn app.main:app --port 8000
     .venv-rag\Scripts\python scripts\seed_hard_corpus.py --base http://127.0.0.1:8000 --purge

2) 连"回答是否相关"一起验收（会调用 LLM 产生费用，可用 --limit / --only 先小范围试）
     .venv-rag\Scripts\python scripts\seed_hard_corpus.py --base http://127.0.0.1:8000 --skip-upload --ask
     .venv-rag\Scripts\python scripts\seed_hard_corpus.py --skip-upload --only E12,E13,E14 --ask

   输出会给出：每题期望文档的排名、top-3 命中了哪几篇、回答覆盖了哪些要点、
   以及库外探针题是否正确拒答。

四、想要 PDF？
------------------------------------------------
     .venv-rag\Scripts\python scripts\seed_hard_corpus.py --make-pdf
   需要 reportlab（体积小）：.venv-rag\Scripts\python -m pip install reportlab
   生成物在 sample_docs/hard/pdf/，其中 99_扫描件_无文本层.pdf 是"图片型 PDF"，
   上传它应当得到明确的 OCR 提示（这是预期行为，不是 bug）。
   PDF 的价值在于验证另一条链路：解析按页 → 分块带页码 → 引用能精确到"第几页"。

五、本机实测基线（4 篇简单文档 + 7 篇困难文档混库）
------------------------------------------------
   检索：11/11 命中，且期望文档都排在第 1 位；3 道探针题无期望文档（正确）
   回答：要点覆盖 10/10；3 道探针题全部正确拒答

   如果你的结果明显更差，按这个顺序查：
     ① chunk_size 是否被调得过大/过小（基线 500/50）
     ② RERANK_ENABLED 是否被关掉（关掉会明显掉质量）
     ③ 库里是否混进了大量同主题文档（干扰变强，属于正常难度上升）

六、把它接进评测框架（可选）
------------------------------------------------
     .venv-rag\Scripts\python scripts\make_hard_eval_set.py
     .venv-rag\Scripts\python scripts\eval_agentic.py --mode both --tag hardcorpus ^
         --set data/eval_set_hardcorpus.json --top-k 4
   这样就能得到"朴素 RAG vs Agentic RAG"在这批困难语料上的完整指标对比。
