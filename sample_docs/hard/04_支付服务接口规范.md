# 支付服务接口规范（PayCore v3）

版本：3.1.2　｜　状态：生效中　｜　维护：支付中台组

本文是**接口契约**，字段名与错误码为强制要求，实现方不得自行改名。

---

## 1. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/paycore/v3/payments` | 创建支付单 |
| GET | `/paycore/v3/payments/{payment_no}` | 查询支付单 |
| POST | `/paycore/v3/payments/{payment_no}/cancel` | 撤销支付单 |
| POST | `/paycore/v3/refunds` | 发起退款 |

## 2. 创建支付单

请求头：

| 头 | 必填 | 说明 |
| --- | --- | --- |
| `X-Pay-Merchant` | 是 | 商户号，形如 `MCH_88012` |
| `X-Pay-Sign` | 是 | 签名（见第 5 节） |
| `Idempotency-Key` | 否 | 幂等键，**同一商户下 24 小时内唯一** |

请求体关键字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `merchant_order_no` | string(64) | 是 | 商户侧订单号，**全局唯一** |
| `amount_cent` | int | 是 | 金额，**单位：分**（不是元！） |
| `currency` | string(3) | 是 | `CNY` / `USD`；默认 `CNY` |
| `channel` | string | 是 | `wxpay` / `alipay` / `unionpay` |
| `notify_url` | string(256) | 否 | 异步通知地址，**必须 https** |
| `expire_seconds` | int | 否 | 支付单有效期，默认 **900**，最大 7200 |

响应体：

```json
{
  "payment_no": "PAY20260408000001",
  "status": "created",
  "amount_cent": 1990,
  "channel": "wxpay",
  "pay_params": { "prepay_id": "wx08103000abc" },
  "created_at": "2026-04-08T10:30:00+08:00"
}
```

## 3. 状态机

`created` → `paying` → `paid` → （可选）`refunding` → `refunded`
另有终态：`cancelled`（超时或主动撤销）、`failed`（渠道明确失败）。

**约束**：只有 `created` / `paying` 可撤销；`paid` 之后只能走退款。
撤销成功返回 `cancelled`，**不是** `closed`（`closed` 是 v2 的旧值，已废弃）。

## 4. 退款

- 退款金额 `refund_amount_cent` **不得大于** 原支付金额，且**累计退款额**不得超过原额。
- 退款为**异步**：创建后返回 `refunding`，最终结果通过 `notify_url` 推送（或轮询查询接口）。
- 部分退款支持多次；全额退款后支付单状态变为 `refunded`。
- 退款到账时效：微信 **1~3 个工作日**，支付宝 **1~2 个工作日**，银联 **3~7 个工作日**。

## 5. 签名规则

1. 取所有**非空**请求参数（含请求体与 `X-Pay-Merchant`），按 key 的 **ASCII 升序**排序；
2. 拼成 `k1=v1&k2=v2...`（**不**做 URL 编码）；
3. 末尾拼接 `&key={商户密钥}`；
4. 做 **HMAC-SHA256**，结果转**大写十六进制**，放入 `X-Pay-Sign`。

> 常见错误：① 用了 URL 编码后再签名；② 小写十六进制；③ 漏掉 `X-Pay-Merchant`。

## 6. 错误码

| 错误码 | HTTP | 含义 | 是否可重试 |
| --- | --- | --- | --- |
| `PAY_PARAM_INVALID` | 400 | 参数校验失败 | 否（改参数后重试） |
| `PAY_SIGN_INVALID` | 401 | 签名校验失败 | 否 |
| `PAY_ORDER_DUPLICATE` | 409 | 商户订单号重复 | 否（用幂等键查询结果） |
| `PAY_AMOUNT_MISMATCH` | 409 | 退款金额超额 | 否 |
| `PAY_CHANNEL_TIMEOUT` | 504 | 渠道超时 | **是**（指数退避，最多 3 次） |
| `PAY_RATE_LIMITED` | 429 | 触发限流 | 是（遵守 `Retry-After`） |

## 7. 幂等与重试

- 创建支付单：携带相同 `Idempotency-Key` 重复提交，返回**首次创建的结果**（HTTP 200，不新建单）。
- 渠道超时（`PAY_CHANNEL_TIMEOUT`）：必须重试，但**必须复用同一个 `merchant_order_no`**，
  否则会产生重复支付单。
- 查询接口（GET）天然幂等，可放心重试。

## 8. 限额与风控

- 单笔限额：微信 **50,000 元**，支付宝 **100,000 元**，银联 **20,000 元**。
- 单商户日累计限额默认 **500 万元**，可申请提额（需风控审批）。
- 命中风控时返回 `PAY_PARAM_INVALID` 并附带 `risk_id`，需人工介入，**不要盲目重试**。
