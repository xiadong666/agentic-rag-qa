# 网关与鉴权接入说明（Nexus Gateway v2.4）

> 文档状态：现行有效　｜　最后更新：2026-03-11　｜　Owner：平台架构组

本文面向需要在业务系统里接入 **Nexus Gateway**（公司自研 API 网关）的研发同学。
阅读完本文，你应该能独立完成：申请接入、配置路由与鉴权、排查 4xx/5xx。

---

## 1. 概念与术语

- **AGT**：Access Gateway Token，网关签发的访问令牌，用于业务系统之后端服务之间调用，**不是**给浏览器用的。
- **UAT（User Access Token）**：终端用户令牌，走 **OAuth2 授权码**（Authorization Code）流程签发。
- **准入标识**：`app_id`，形如 `nx-app-7f3a`，由平台在**申请单审批通过**后邮件下发。
- **上游**：网关转发到的后端服务，要求暴露健康检查 `GET /internal/health`。

> 术语提示：早期文档里把 AGT 写成「服务票据（Service Ticket）」，
> 现已统一为 AGT。看到 Service Ticket 时按 AGT 理解即可。

## 2. 接入流程（五步）

1. 在 **DevPortal → 服务接入 → 新建接入单** 填写：系统名、负责人、预计 QPS、是否需要外网。
2. 选择鉴权方式（三选一）：`AGT`、`UAT(OAuth2)`、`双向 TLS`。**默认推荐 AGT**。
3. 平台审批（通常 1 个工作日）后，邮件收到 `app_id` 与 **初始 AGT**（仅首次展示）。
4. 在上游服务里接入网关 SDK：`nexus-gateway-sdk`（Java / Go / Python 三种）。
5. 配置路由并发布：路由分为**灰度**与**全量**两档，灰度按 `X-Nx-User` 头做百分比分流。

## 3. 路由配置示例

路由配置采用 YAML，例：把 `/api/orders/**` 转发到订单服务，并强制 AGT 鉴权。

```yaml
route:
  id: orders-v1
  match:
    prefix: /api/orders
  upstream: http://orders-svc.default.svc:8080
  auth:
    type: agt
    required: true
  timeout_ms: 3000
  retry:
    attempts: 2
    on: [502, 503, 504]
```

**关键约束**：`timeout_ms` 的默认值是 **800 毫秒**；上例显式覆盖为 3000。
注意它**不是** 5000 —— 早期版本曾用 5000，自 v2.0 起已下调。

## 4. 鉴权与令牌

| 鉴权方式 | 适用场景 | 令牌有效期 | 刷新方式 |
| --- | --- | --- | --- |
| AGT | 服务端到服务端 | 30 天 | 到期前 7 天在 DevPortal 轮换 |
| UAT | 面向终端用户 | 2 小时 | refresh_token（有效期 14 天） |
| 双向 TLS | 强合规链路 | 证书 1 年 | 重新签发证书 |

- AGT 放在请求头 `X-Nx-Agt`，**不要**放 `Authorization`（那是 UAT 的位置）。
- 网关对同一 `app_id` 的 AGT 轮换有**双活窗口**：新旧令牌并存 24 小时，便于平滑切换。
- 令牌泄露处理：立即在 DevPortal「吊销」并重新签发；网关会在 **5 分钟内**生效吊销。

## 5. 错误码

| HTTP | 错误码 | 含义 | 处理建议 |
| --- | --- | --- | --- |
| 401 | NX-1001 | AGT 缺失或格式错误 | 检查 `X-Nx-Agt` 头 |
| 401 | NX-1002 | AGT 已过期 | 到 DevPortal 轮换 |
| 403 | NX-2001 | `app_id` 无该路由权限 | 在接入单里加权限并重新发布 |
| 429 | NX-3001 | 触发限流 | 退避重试；默认配额 200 QPS/系统 |
| 502 | NX-4001 | 上游不可达 | 检查上游健康检查与端口 |
| 504 | NX-4002 | 上游超时 | 确认上游耗时，必要时调大 `timeout_ms` |

> 注意：**429 返回的 `NX-3001` 一定带 `Retry-After` 头**（单位秒），
> 客户端必须遵守；不遵守会被升级为 10 分钟熔断。

## 6. 观测与排障

- 每次请求网关会注入 `X-Nx-Trace-Id`；排障时用它到 **Trace 平台**检索全链路。
- 常用指标：`nx_gateway_requests_total`、`nx_gateway_upstream_latency_ms`（P99）。
- 排障顺序建议：① 看 Trace 定位失败节点 → ② 看错误码表 → ③ 看上游健康检查。
